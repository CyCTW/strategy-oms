# 策略訂單核心設計

此版本是可嵌入策略程式的 OMS 模組，使用模擬 Gateway 驗證，不連接真實交易帳戶。

v0.4 價格索引的 Pool、差異更新、穩定 Handle 與候選採用決策見 [price-index.md](price-index.md)。預設保留標準 B-tree；不是把所有樹結構一律替換成自訂結構。

v0.3 的單張最新意圖介面見 [single-orders.md](single-orders.md)；群組目標、子單配置、停止／拒絕政策與排程契約見 [groups.md](groups.md)。它們位於同一個 Engine，共用實體訂單 reducer，底層仍保持每張實體訂單最多一筆在途請求。

## 一致性邊界

- 單一寫入者處理命令與標準化回報，索引更新完成後才回傳通知。
- 訂單 ID 穩定；每次新單、撤單、改單使用獨立且不可重用的 request ID。
- 同一張單最多一個待確認操作；在途期間可接受最新撤改意圖，確認後再由事件迴圈執行，沒有多筆同時在途的連鎖改單。
- 已確認價格／數量、待確認請求與最新策略意圖分開；只有實際提交送出才改變 pending 與預留量。撤單待確認期間仍保留剩餘量。
- Gateway 將場所、帳戶、交易日、session 與外部字串 ID 映射成無碰撞的內部 ID；不可直接使用有碰撞可能的字串雜湊當唯一識別。
- 所有標準化回報來源必須提供連續序號。不同來源共用成交識別，以避免主回報與 Drop Copy 重複入帳。
- 改單僅表示原子修改同一張實體訂單。撤舊下新必須是兩張實體訂單。

## 查詢

書本作用域包含策略、帳戶、場所、商品、買賣方向。價格是有號整數固定精度，不使用浮點數。商品 tick、價格範圍、數量單位由 Gateway／產品規則驗證。

價格層包含已確認剩餘量、待新單量、待撤剩餘量，以及待改入／改出數量。待撤量屬於已確認量的一部分，不能直接相加。查詢回傳版本和未知狀態數，策略不能把過期資料當成即時事實。

## 回報與恢復

- 拒絕撤改單只結束該次請求，不恢復舊的成交量。
- Timeout 代表結果未知；不自動重送、不釋放風險額度。
- 成交更正引用原成交，調整成交帳；不自動假定交易所重新開啟終結單。
- 正常使用先寫日誌、後發布可送出的 Gateway 命令。模擬與量測可使用記憶體日誌。
- 重播不得再送 Gateway 命令。重啟後可保存最新撤改意圖，但未結單與待確認請求必須對帳，才可實際執行撤改。
- 日誌無法消除「交易所已收單，但本地尚未知道」的區間；外部對帳仍為必要步驟。

## 第一版驗證

1. 待新單可查，避免策略因為尚未確認而重複補量。
2. 新單確認前成交、部分成交、全成。
3. 撤單途中成交；撤單拒絕不回退成交。
4. 改單途中成交；接受才移動價格層，拒絕保留舊價格。
5. 回報重複、成交跨來源重複、來源序號缺口。
6. Timeout、成交更正、外部強制撤單、失效。
7. 重播、重啟對帳、損壞日誌拒絕載入。
8. 容量／數量界限、過期版本、錯誤事件不改變狀態。

## 後續介接

真實 Gateway 的 session 恢復、外部委託 ID 映射、行情、帳戶部位／資金風控、快照壓縮、日誌輪替及服務部署不屬於目前模擬核心。部署前須依指定市場補上這些元件。
